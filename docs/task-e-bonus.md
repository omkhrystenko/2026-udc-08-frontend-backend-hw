# Task E (bonus) — Шлях 2: автоматична перевірка доступності

## Інструмент

**axe-core 4.13** через `@axe-core/playwright` 4.13, у справжньому Chrome
(`playwright-core` 1.63, `channel: "chrome"` — без завантаження окремого браузера).
Набір правил: `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`,
`best-practice`.

Запуск — частина [`scripts/browser-check.mjs`](../scripts/browser-check.mjs):

```bash
cd app && rm -f notes.db && npm run dev          # чиста база, окремий термінал
cd scripts && npm install && npm run check        # BASE=http://… для іншої адреси
```

Залежності живуть у `scripts/package.json`, окремо від `app/`: застосунок
лишається без збірки й без зайвих пакетів.

axe проганяється в **чотирьох станах**, бо порушення залежать від того, що на
екрані: вид «Активні», вид «Архів» з нотаткою, порожній архів і **темна тема**
(`color-scheme: light dark` у засіяному CSS означає, що вимоги до контрасту
діють в обох). Поруч із axe скрипт робить перевірки, яких axe не вміє, — про
них нижче, бо саме вони виявились найважливішими.

## Що знайшло

Той самий скрипт на трьох версіях UI
([вивід для агента](evidence/browser-check-agent.txt),
[для моєї](evidence/browser-check-mine.txt)):

| Правило axe | Вплив | Засіяний UI | UI агента | Мій UI |
|---|---|---|---|---|
| `aria-required-children` — `role="tablist"` без жодного `role="tab"` | critical | — | **1** на кожному виді | — |
| `color-contrast` у темній темі | serious | 3 *(хибні)* | 6 *(хибні — з тим самим `body { background: Canvas }` стає 0)* | 0 |
| `landmark-one-main` — немає `<main>` | moderate | 1 | 1 | — |
| `region` — вміст поза орієнтирами | moderate | 4 | 3–4 | — |
| **Разом по всіх станах** | | | **FAIL у 4 з 4** | **0 у 4 з 4** |

### Хибне спрацювання, яке довелося розібрати

axe повідомив про кнопки в темній темі **«контраст 1.07:1, білий на
`#f7f7f7`»**. Скріншот показав протилежне — білий текст на майже чорному,
читається чудово ([`ui-archive-dark.png`](evidence/ui-archive-dark.png)).

Причина: фон кнопки напівпрозорий (`#8881`), а в `body` не було власного фону.
axe накладає напівпрозорий колір на те, що бачить під ним, — і за відсутності
явного фону бере білий, хоча браузер у темній темі малює полотно
`rgb(18, 18, 18)`. Засіяний UI мав ті самі 3 «порушення».

Замість того щоб просто відписатись «false positive», я перевірив гіпотезу:
`body { background: Canvas; color: CanvasText; }` — системні кольори, що
розв'язуються в справжнє полотно. Після цього axe сам обчислив
`rgb(18, 18, 18)` і показав **0 порушень в обох темах**. Користувачу нічого не
змінилось, а інструмент перестав брехати — наступне справжнє порушення
контрасту не загубиться серед хибних.

## Чого axe не знайшов — і це головне

Із **шести** дефектів доступності й UX в UI агента axe побачив **один**
(`tablist`). Решту знайшли перевірки, написані руками в тому самому скрипті:

| Дефект в UI агента | axe | Хто знайшов |
|---|---|---|
| `role="tablist"` без вкладок | ✅ critical | axe |
| Однакові імена «Архівувати», «Архівувати» — не видно, яка нотатка | ❌ | `a11y:archive-button-names-unique` (axe не має такого правила) |
| Після архівування фокус падає на `<body>` | ❌ | `a11y:focus-after-archive` |
| Нотатка зникає, а скрінрідер нічого не чує | ❌ | `a11y:change-announced` |
| Форма «Додати» видима в архіві, хоча має `hidden` | ❌ | `flow:add-form-hidden-in-archive` — і то лише після того, як я **побачив** це на скріншоті |
| Подвійний клік скасовує архівування | ❌ | `flow:double-click-still-archived` |

Це закономірно. axe перевіряє **статичний знімок DOM** на відповідність
правилам: чи є ролі, імена, контраст. Він не знає, що сталося **між** двома
станами — куди подівся фокус, чи прозвучало оголошення, чи збігається те, що
видно, з тим, що позначено в DOM. А найболючіші для користувача клавіатури й
скрінрідера дефекти живуть саме там: у переходах.

## Що полагодили, а що лишили і чому

**Полагодили:**

- `tablist` → нативні `<input type="radio">` у `<fieldset>` з `<legend>`.
  Жодного ручного ARIA — семантика й навігація стрілками від браузера.
- `<main>` навколо вмісту — закриває засіяні `landmark-one-main` і `region`.
- `body { background: Canvas }` — прибирає хибні порушення контрасту.
- Доступні імена «Архівувати: <назва нотатки>» (починаються з видимого
  тексту — WCAG 2.5.3); те саме для засіяного «Видалити».
- Фокус після дії → сусідня кнопка або порожній стан; `role="status"`
  оголошує результат.
- `[hidden] { display: none !important }`.

**Лишили свідомо:**

- **Поля форми мають лише `placeholder` і `aria-label`, без видимого `<label>`.**
  axe це приймає, бо доступне ім'я є. Але плейсхолдер зникає, щойно почнеш
  друкувати, і людина з порушенням пам'яті чи уваги губить, яке поле
  заповнює. Це засіяна розмітка форми, яка до фічі архівування не належить, —
  тож я додав `aria-label` для надійного імені, але видимі підписи не
  вводив, щоб не розширювати PR за межі задачі. Це перше, що я б зробив
  наступним.
- **Дата `created_at` у сирому форматі SQLite** (`2026-09-22 16:54:57`) —
  читається скрінрідером як набір чисел. Теж засіяне, теж поза скоупом.

## Чи збігається знайдене з типовими дефектами зі слайдів

| Типовий дефект | Тут |
|---|---|
| **Контраст** | Так — але як **хибне** спрацювання. Корисний урок: автоматичний звіт про контраст треба звіряти зі скріншотом, особливо з напівпрозорими кольорами й темною темою |
| **`alt` у зображень** | Не застосовно — зображень немає |
| **Підписи полів** | Частково: засіяні поля мали лише `placeholder`. axe не скаржиться, бо формально ім'я є; реальна проблема лишається (див. вище) |
| **Порожні кнопки / посилання** | Ні — але **неоднозначні** кнопки так: «Архівувати» × N. axe не має правила на це, тож «кнопка не порожня» не означає «кнопка зрозуміла» |
| **Мова документа** | Чисто: засіяний `<html lang="uk">` |

І одне, чого на слайдах як окремого пункту не було, а тут виявилось головним:
**ARIA, додана «для доступності», зробила гірше**. Єдине критичне порушення в
усьому прогоні — не забута атрибутика, а зайва: `role="tablist"`, який
пообіцяв скрінрідеру вкладки й не дав жодної. Нативний елемент без жодного
`aria-*` закрив це повністю.
